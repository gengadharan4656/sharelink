Technical Architecture & SLTP v2

An in-depth guide to ShareLink's wire framing, cryptographic primitives, and offline local network streaming engine.

1. System Architecture Overview

ShareLink operates on a decentralized, peer-to-peer, offline-first model. When an Android user initiates a transfer session:

  1. The Android application starts an embedded local HTTP server (bound to port 8080 or a dynamic fallback port).
  2. A 256-bit session token and pairing secret are generated locally.
  3. A pairing QR code is generated containing: 
    http://<sender-ip>:<port>/s/<sessionToken>#<pairingSecret>
  4. Clients connect over the local physical network (Wi-Fi router or portable mobile hotspot).
ℹ️

Important: Architectural Separation

This website (hosted on GitHub Pages) is purely an informational and download portal. It never acts as a transfer proxy or relay. File transfers occur entirely peer-to-peer across your local Wi-Fi router or Android hotspot.

2. SLTP v2 Wire Protocol Specification

The ShareLink Transfer Protocol version 2 (SLTP v2) structures all streaming data into deterministic, binary-framed chunks with a 40-byte fixed header: 

+-------------------------------------------------------------+
| SLTP v2 40-Byte Binary Frame Structure                     |
+-------------------------------------------------------------+
| Byte 00..03 : Magic Number 0x534C4632 ('SLF2')              |
| Byte 04..04 : Protocol Version (0x02)                       |
| Byte 05..05 : Flags (Bit 0: IsLastChunk, Bit 1: IsEncrypted)|
| Byte 06..07 : Reserved / Future use                         |
| Byte 08..15 : 64-bit Chunk Index (Big-Endian)               |
| Byte 16..23 : 64-bit Byte Offset in File (Big-Endian)       |
| Byte 24..27 : 32-bit Plaintext Payload Length               |
| Byte 28..31 : 32-bit Ciphertext Payload Length              |
| Byte 32..43 : 96-bit (12-byte) AES-GCM IV Nonce             |
+-------------------------------------------------------------+
| Byte 44..N  : Ciphertext Payload + 16-byte AEAD Auth Tag    |
+-------------------------------------------------------------+

Frame Header Fields

  • Magic (4 bytes): 0x534C4632 ASCII representation for SLF2. Confirms wire protocol compatibility.
  • Version (1 byte): 0x02 representing SLTP v2.
  • Flags (1 byte): Bitmask for chunk sequencing:
    • 0x01: isLastChunk flag indicating final payload chunk.
    • 0x02: isEncrypted flag indicating AEAD ciphertext.
  • Chunk Index (8 bytes): Monotonically increasing sequence index starting at 0.
  • Byte Offset (8 bytes): Exact byte seek position for chunk resumption and RFC 7233 range seeks.
  • Lengths (8 bytes): Plaintext size and Ciphertext size (Plaintext + 16-byte tag).
  • IV Nonce (12 bytes): 96-bit unique vector conforming to NIST SP 800-38D.

3. Cryptographic Security Invariants

AEAD Authenticated Encryption

Every chunk is encrypted with AES-256-GCM. Galois/Counter Mode provides both confidentiality and data authenticity:

  • Per-File Key Isolation: From the master session key, independent 256-bit symmetric keys are derived for each file using HKDF-SHA256(sessionKey, info="ShareLink-v2-FileKey-download-<fileId>"). This eliminates the risk of nonce reuse across multiple files in the same session.
  • Monotonic Nonces: The 12-byte IV consists of a 4-byte random invocation salt followed by the 8-byte big-endian chunk index.
  • Directional Isolation: Uploads (client to server) and downloads (server to client) derive separate directional keys (c2s vs s2c), preventing reflection attacks.
  • Progressive SHA-256 Digest: All incoming chunks are validated through a continuous streaming SHA-256 digest on the receiver before the temporary .part file is atomically renamed.

4. High-Performance Bounded Streaming

To maintain high throughput on low-memory devices (such as 4 GB – 8 GB RAM phones and laptops), ShareLink implements:

  • 512 KB Chunk Slicing: Chunks are sized to maximize Wi-Fi packet aggregation while maintaining low memory pressure.
  • Socket Backpressure: Sender uses await response.flush() on the HTTP socket so fast disk reads do not overwhelm receiver consumption buffers.
  • Resume Recovery: RFC 7233 Range: bytes=start- headers combined with x-sharelink-resume-offset allow broken transfers to resume without restarting.

5. Network Troubleshooting Guide

Android Portable Hotspot Mode (Recommended for Anywhere Sharing)

When no Wi-Fi router is available, turn on your Android Portable Hotspot. Connect the receiver to the hotspot. The sender automatically detects the hotspot gateway interface (e.g., 192.168.43.1) and opens the transfer port.

Windows Firewall Configuration

If receiving on a Windows browser, no configuration is needed. If running a future desktop native server, ensure incoming TCP traffic on port 8080 is allowed on Private Networks in Windows Defender Firewall.
